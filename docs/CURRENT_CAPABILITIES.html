Find your way through Umicom Kernel

Umicom Kernel is an independent native-kernel repository. The complete OS distribution, graphical desktop and applications belong to other repositories. The kernel does not depend on the full Umicom Framework. Application portability needs a System Services adapter above the kernel's native ABI.

Start with the boundary

  1. Read the architecture and the portability and System ABI guide. These distinguish privileged mechanisms from user-space services.
  2. Choose a capability below and read its interface and implementation together. A registered fixture describes an intended check; it is not evidence that a particular machine or revision has passed it.
  3. Use the capability's validation guide when qualifying that specific profile. Record the source revision, toolchain, guest configuration and actual result. Keep hardware claims limited to the configuration exercised.

Parent references, collision checks, source and parent read-only flags, subtree depth and whole-image preservation are checked. A move requires an existing destination slot and explicit Finish. See Moving FAT16 files and directories. This remains a trusted Kernel interface, without journalling or automatic recovery.

Understand persistence before extending it

The FAT16 editing source stages bounded updates behind persistent dirty guards and performs explicit ordered finalisation. Closing an owner releases resources; it does not promise to undo bytes already written. An unfinished dirty volume is refused by the relevant admission checks. Refusal protects evidence, but does not itself reconstruct an interrupted transaction.

Directory creation, empty removal and bounded parent extension use the same explicit Stage and Finish protocol as regular-file changes. Do not describe that protocol as journalling or automatic crash recovery. General writable VFS access, long filenames, broader driver coverage, networking and graphical desktop integration still require their own implementation and qualification. Read the directory guide's limits before changing capacities or granting an untrusted process a write handle.

Keep OS integration deliberate

The RISC-V research profile is a native-kernel execution route. An installable Umicom OS distribution and its existing kernel choice remain separate products. Adding a native-kernel profile should preserve the distribution's working routes and declare which device, service and application capabilities are actually available. Linking Framework directly into privileged kernel code would bypass that boundary.
